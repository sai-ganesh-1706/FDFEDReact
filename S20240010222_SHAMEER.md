## 2. Candidate Domain & Role Analysis (In Short)

The **Candidate** is the primary end-user and beneficiary of CareerNest. Within an academic placement ecosystem, the candidate represents an enrolled student seeking career opportunities (internships, full-time engineering roles, and corporate drives).

```
+--------------------------------------------------------------------------------------------------+
|                                    CANDIDATE WORKFLOW ENGINE                                     |
+--------------------------------------------------------------------------------------------------+
|                                                                                                  |
|   1. PROFILE SETUP         2. DISCOVERY             3. APPLICATION           4. TRACKING         |
|   +------------------+     +------------------+     +------------------+     +-----------------+ |
|   | Academic Profile |     | Browse Drives    |     | Eligibility Check|     | Pipeline Stages | |
|   | CGPA & Branch    | ==> | Advanced Filters | ==> | Multi-Step Wizard| ==> | Assessment Links| |
|   | Resumes & Skills |     | Bookmark / Save  |     | Resume Selection |     | Recruiter Rating| |
|   +------------------+     +------------------+     +------------------+     +-----------------+ |
|                                                              ▲                        │          |
|                                                              │                        ▼          |
|                                                     5. ALUMNI REFERRAL       6. PLACEMENT &      |
|                                                     +------------------+        OFFER STAGE      |
|                                                     | Company Matching |     +-----------------+ |
|                                                     | Verified Alumni  |     | Offer Letter    | |
|                                                     | Endorsement Pitch|     | Direct Onboard  | |
|                                                     +------------------+     +-----------------+ |
+--------------------------------------------------------------------------------------------------+
```

### Key Candidate Attributes & Domain Constraints
1. **Academic Credentials & Eligibility**:
   - Every candidate is defined by university attributes: Department (`CSE`, `ECE`, `IT`), Current CGPA (e.g., `8.7`), Backlog count (`0`), Roll Number (`S20240010222`), and Graduation Batch (`2024-2028`).
   - Corporate job drives enforce strict eligibility criteria (e.g., `minCgpa >= 7.5`, eligible branches: `["CSE", "IT"]`, max active backlogs: `0`). The candidate dashboard automatically computes live eligibility checks before allowing application submission.
2. **Asymmetric Information Friction**:
   - Traditional placement drives suffer from missed circular deadlines, scattered email threads, and untracked recruitment rounds. The Candidate Dashboard resolves this by consolidating circular noticeboards, upcoming calendar assessments with direct meeting links, and application status stages in one unified view.
3. **Alumni Capital & Mentorship**:
   - Securing job referrals requires networking with institutional alumni working at target enterprises. The candidate portal algorithmically normalizes company names to match candidates with relevant alumni from their own college, facilitating direct referral requests.
4. **Dynamic Resume & Portfolio Representation**:
   - Modern campus recruitment demands specialized representation (e.g., LeetCode handles, project repositories, certification credentials). The profile module acts as a live digital portfolio that syncs bidirectionally with the backend.

### G. Centralized State Store, UI Context & Custom Hooks (`React/React/src/roles/candidate/`)

1. **`context/StoreContext.jsx` (Master Candidate Data Layer)**:
   - **Unified Data Hydration (`load`)**: Coordinates concurrent REST API requests via `Promise.all()` fetching:
     - Candidate user credentials (`GET /users/:id`)
     - Placement opportunities (`GET /opportunities`)
     - Application records (`GET /applications/my`)
     - Notifications (`GET /notifications`)
     - Saved drive IDs (`GET /features/candidate/saved-drive-ids`)
     - Assessments & interview schedules (`GET /assessments/my`)
     - Referral requests (`GET /referrals/my`)
     - Placement circulars (`GET /announcements`)
   - **Silent Background Sync**: Sets up a 20-second interval timer that polls data in the background (`silent: true`) when the document tab is active, updating lists without overwriting active form inputs.
   - **Debounced Server Auto-Save**: Listens to changes in `currentUser` and `profileResumeData`; automatically debounces saves (`700ms`) via `api.put(/users/:id, payload)` after comparing against `lastSaved` ref cache.
   - **Company Key Normalizer (`referralCompanyKey`)**: Strips common corporate suffixes (`Inc`, `LLC`, `Corp`, `Technologies`, `Pvt Ltd`) to enable fuzzy company matching between job postings and registered alumni.
   - **Centralized Dispatcher Actions**: Exports `applyToJob`, `withdrawApplication`, `toggleSaved`, `markAllNotificationsRead`, `markNotificationRead`, `fetchAlumniForCompany`, and `requestReferral`.

2. **`context/UIContext.jsx` (Global Modal & Notification State)**:
   - Manages topbar notification drawer state (`notifOpen`, `toggleNotif`, `closeNotif`).
   - Manages "Ask a Query" dialog lifecycle (`askQueryOpen`, `queryMessage`, `submitQuery`).
   - Manages platform success modal state (`successModal`, `showSuccess`, `closeSuccess`).
   - Computes unread notification count across the candidate workspace.

3. **`hooks/useToast.js` (Transient Alert Hook)**:
   - Reusable notification hook with auto-dismiss timer (`3000ms`), managing toast visibility and messages for quick user feedback.

## 5. Supporting Backend Integration & Endpoints Consumed

The candidate frontend communicates with the **NestJS Backend** through the unified Axios client (`services/api.js`), utilizing session headers (`x-user-id`, `x-role: Candidate`, `x-college-id`):

| Backend Endpoint | HTTP Method | Frontend Caller (`StoreContext` / Page) | Purpose & Data Payload |
| :--- | :---: | :--- | :--- |
| `/users/:id` | `GET` | `StoreContext.load()` | Fetches candidate credentials, CGPA, department, and resume JSON |
| `/users/:id` | `PUT` | `StoreContext` (debounced auto-save) | Persists profile updates, skills, links, and resume records |
| `/opportunities` | `GET` | `StoreContext.load()` | Loads all approved placement drives scoped to candidate's college |
| `/applications/my` | `GET` | `StoreContext.load()` | Fetches candidate's active and historical job applications |
| `/applications` | `POST` | `StoreContext.applyToJob()` | Submits a new job application with resume file and screening answers |
| `/applications/:id/withdraw` | `PATCH` | `StoreContext.withdrawApplication()`| Allows candidate to withdraw an active job application |
| `/features/candidate/saved-drive-ids` | `GET` | `StoreContext.load()` | Fetches array of bookmarked drive IDs |
| `/features/candidate/drives/:id/save` | `POST` / `DELETE` | `StoreContext.toggleSaved()` | Saves or removes a drive from bookmarked drives |
| `/assessments/my` | `GET` | `StoreContext.load()` | Loads upcoming online assessments and interview meetings |
| `/referrals/my` | `GET` | `StoreContext.load()` | Fetches all candidate referral requests and alumni responses |
| `/referrals` | `POST` | `StoreContext.requestReferral()` | Dispatches a referral request to a matched alumnus |
| `/users/alumni-directory` | `GET` | `StoreContext.fetchAlumniForCompany()`| Queries registered alumni to find matches for target hiring companies |
| `/notifications` | `GET` | `StoreContext.load()` | Loads student notifications (status changes, reminders) |
| `/notifications/read-all` | `PATCH` | `StoreContext.markAllNotificationsRead()`| Marks all candidate notifications as read |
| `/notifications/:id/read` | `PATCH` | `StoreContext.markNotificationRead()` | Marks a specific notification as read |
| `/announcements` | `GET` | `StoreContext.load()` | Retrieves placement cell circulars and urgent notices |
